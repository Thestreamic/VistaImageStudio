================================================================
1. PRODUCT CONCEPT AND POSITIONING
================================================================

1.1 What it is
--------------
Vista Image Studio is a privacy-first, local-first photo editor for
people who make social posts. Open a photo (including iPhone HEIC),
grade it, crop for Instagram / Story / YouTube, cut a background,
erase an object, lay out a collage, add text or a logo, save a
.lumen project, and export a creator pack. Everything runs on the
user's machine.

One-line product claim (docs/FEATURES.txt):

  Local photo editor — open a photo, Optimize Image, crop for social,
  apply looks, erase objects, cut backgrounds, add text/logo, save
  .lumen, export a creator pack. Everything stays on your PC (no
  cloud, no account, no LLM).

1.2 Who it is for
-----------------
Primary: creators and small businesses who need social-ready stills
without uploading photos to a SaaS editor.

Secondary: anyone who wants a desktop or browser editor that works
offline after assets are on disk.

Not for: RAW photography pipelines, DAM / cloud libraries, team
collaboration, generative fill from an LLM, or "chat with your
photos" products.

1.3 Positioning vs typical editors
----------------------------------
  - Not Photoshop. Layer stack is real, but the UX is social-post
    first (looks, 4:5 crop, export kit, collages, templates).
  - Not Canva-in-the-cloud. Templates and text exist, but pixels
    never leave the device and there is no account.
  - Not an LLM photo assistant. Command parsing is a local keyword
    schema. Unknown phrases never become edits (docs/AI.md).
  - Dual surface: packaged Electron app and a static web export
    (GitHub Pages). Same renderer code. Different hosts.

1.4 Privacy model (product promise)
-----------------------------------
  - No account, no telemetry, no photo upload API in the app
    (docs/PRIVACY.md).
  - Pixels live on HTMLCanvasElement in the renderer. AI runs in a
    Web Worker via onnxruntime-web WASM.
  - Production CSP connect-src is: 'self' blob: data:
  - Export re-encodes the canvas, so camera EXIF is not copied.
  - ONNX weights (MODNet, MiDaS, LaMa) sit on disk under
    public/models/ (dev) or process.resourcesPath/models (packaged).
    They are not fetched at edit time (CSP forbids it).
  - Media bin blobs persist in IndexedDB on this device
    (vista-media-library). They are not a cloud library.
  - Command chat (when used) stores text only in localStorage key
    vista-chat-history — no pixels, no file paths.

1.5 What this product is NOT
----------------------------
  - There is no remote application backend, no REST photo API, no
    S3 bucket, no auth server, no LLM endpoint.
  - docs/index.html (marketing site) may call the GitHub API. That
    page is not shipped inside the desktop app (docs/PRIVACY.md).
  - Cloud sync is explicitly out of scope unless it is opt-in later
    and never the default (docs/ROADMAP.md).

1.6 License / distribution posture
----------------------------------
LICENSE is a proprietary beta agreement. Source may be visible in a
public repo for feedback; that does not make the product open
source. package.json license is UNLICENSED. electron-builder
publish is null (no auto-update channel).

2. HIGH-LEVEL ARCHITECTURE
================================================================

2.1 Stack (verified)
--------------------
  Electron 33        desktop shell (main + preload)
  Next.js 16.3.3     App Router renderer; static export for packaged
                     and Pages builds (next.config.mjs)
  React 19           UI
  Zustand 5          single editor store
  TypeScript 5.7     renderer (bundler resolution) + electron tsconfig
  Tailwind CSS 4     app/globals.css
  onnxruntime-web    on-device inference (WASM)
  Playwright / Vitest tests

This is not a Next.js server app in production. There are no
app/api routes. Packaged Electron loads a static export as a file:
  dist-electron compiled main loads  out/index.html
Dev Electron loads  http://localhost:3000  (next dev).

2.2 Why Electron + Next static export
-------------------------------------
The renderer is a React SPA. Next is used for the App Router, the
dev server (HMR), and `output: 'export'` so the desktop app does
not need a Node HTTP server at runtime.

next.config.mjs (verified):
  ELECTRON_BUILD=1  -> output export, distDir "out"
  WEB_EXPORT=1      -> output export, distDir "out-web", trailingSlash
  otherwise         -> default Next distDir ".next" (dev / CI build)
  images.unoptimized true  (required for static export)
  turbopack: {}     Next 16 defaults to Turbopack; empty object opts in
  typescript.ignoreBuildErrors true  (build still typechecked in CI
                    via pnpm typecheck)

2.3 Process model
-----------------

  +--------------------------------------------------------------+
  | ELECTRON MAIN  (Node, privileged)                            |
  | electron/main/index.ts                                       |
  |  BrowserWindow, native Menu, dialogs, atomic .lumen write,   |
  |  autosave under userData, CSP header, single-instance lock,  |
  |  splash, quit confirmation                                   |
  |  Does NOT touch image pixels.                                |
  +------------------------------+-------------------------------+
                                 | IPC (allowlisted channels)
  +------------------------------v-------------------------------+
  | PRELOAD  (isolated world)                                    |
  | electron/preload/index.ts                                    |
  |  contextBridge.exposeInMainWorld('lumen', ...)               |
  |  contextIsolation true, nodeIntegration false, sandbox true  |
  +------------------------------+-------------------------------+
                                 | window.lumen
  +------------------------------v-------------------------------+
  | RENDERER  (Chromium, no Node)                                |
  | Next.js static HTML/JS  OR  next dev on :3000                |
  |  lib/platform/bridge.ts   host abstraction                   |
  |  features/editor/         engine + Zustand store             |
  |  features/ai/             worker + ONNX algorithms           |
  |  components/editor/       UI                                 |
  |  IndexedDB media library, localStorage prefs                 |
  +--------------------------------------------------------------+

2.4 Host abstraction
--------------------
Nothing in features/ or components/ should branch on Electron vs
browser except the bridge itself and a few chrome bits (custom
Windows title bar, native file dialogs).

  lib/platform/bridge.ts
    getBridge(): LumenBridge
    isElectron(): boolean   // true iff window.lumen exists

  Electron path: makeElectronBridge() wraps window.lumen.
    openImage returns { name, blob } after converting ArrayBuffer.
  Web path: webBridge uses <input type=file>, <a download>,
    showDirectoryPicker when present, localStorage for autosave.

2.5 Why this split
------------------
Main owns the OS. File dialogs, menus, and window chrome live in
electron/main. Keeping pixels out of main keeps the privileged
process small.

Preload is the only bridge. Unrecognised IPC channel names are
rejected with a console warning (preload/index.ts).

The renderer does not know the host. getBridge() is the seam that
lets the same EditorShell run in next dev, GitHub Pages, and a
packaged .exe.

2.6 Next.js 16 specifics in THIS repo
-------------------------------------
App Router files (only these under app/):
  app/layout.tsx    root HTML, metadata, viewport
  app/page.tsx      default export: <EditorShell />
  app/globals.css   Tailwind + editor chrome tokens

There is no middleware.ts, no route handlers, no server actions
for editing. The editor is a client-side tree ('use client' on
EditorShell and store).

Static export means:
  - no Node server in the packaged app
  - public files (models, ort wasm, icons) must be on disk
  - GitHub Pages uses BASE_PATH / NEXT_PUBLIC_BASE_PATH so assets
    work under https://user.github.io/repo-name/
    (lib/public-url.ts prefixes publicUrl() with that base)

4.3 Compositor
--------------
features/editor/engine/compositor.ts
  class Compositor, singleton export `compositor`

  Per-layer cache of the adjusted bitmap keyed by adjustments hash
  + size. Dragging one slider does not reprocess other layers.
  Identity adjustments blit the source (or a scaled copy).

  render(doc)            full document, watermarks last
  renderOutput(doc)      clipped to live crop (export/print)
  flattenLayer           one layer in document space

  Collage slots: drawDocumentLayer clips circle/rounded/polaroid,
  paints polaroid chrome, applies slot rotation.

Blend modes map to CanvasRenderingContext2D composite operations.

4.10 Project schema (.lumen)
----------------------------
features/editor/project/schema.ts

  PROJECT_SCHEMA_VERSION = 1
  PROJECT_EXTENSION = ".lumen"
  PROJECT_MIME = "application/x-lumen-project+json"
  AUTOSAVE_MAX_BYTES = 12 * 1024 * 1024

A project is UTF-8 JSON, not a ZIP. Assets are embedded PNG (or
JPEG) data URLs so a file copies without a sidecar folder.

Required shape (kind MUST be "lumen-project"):

  {
    "kind": "lumen-project",
    "schemaVersion": 1,
    "id": "doc_…",
    "createdAt": "ISO-8601",
    "modifiedAt": "ISO-8601",
    "fileName": "Shot.png",
    "canvas": { "width": 1080, "height": 1350 },
    "activeLayerId": "layer_…",
    "crop": { "x", "y", "width", "height" } | null,
    "lookId": "…",
    "lookIntensity": 80,
    "lastExport": { ... },
    "brandKit": { "colors": [...], "font": "Inter" },
    "layers": [ { assetId, adjustments, collage*, textData, ... } ],
    "assets": { "asset_…": { "id", "mime", "dataUrl" } }
  }

validate.ts
  JSON.parse only (never eval).
  Assets may only be data:image/png;base64 or data:image/jpeg;base64.
  http(s):, javascript:, file:, data:text, ".." rejected.
  Future schemaVersion -> read-only (export still allowed).
  Max parse size 32 MB. Autosave writer in renderer caps 12 MB.

serialize.ts  canvas -> PNG data URL per layer
migrate.ts    historical shapes up to v1; docs say there are no
              on-disk projects from earlier Vista builds to migrate

5.4 Algorithms (files under features/ai/algorithms/)

  Remove Background. segmentHeuristic kept for tests / local-enhance.

    1. usable selection mask (user marked the object)
    2. else MODNet person matte, only if isUsableSubjectMatte
    3. else estimatePortraitSubject / objectFocusKeep

  back sharp. phoneBlurRadius is a fraction of the short side.

  estimateDepthWithModel (MiDaS) is still in portrait-blur.ts.
  The Bokeh button does not call it.

-----------------------

    DocumentState + brandKit

              Electron: fs:save-project atomicWrite *.lumen

        -> markSaved(path), clearAutosave, addRecent

        -> assertSafeProjectShape (data URLs only)

        -> Web localStorage vista-autosave

================================================================
14. SECURITY AND PRIVACY
================================================================

14.1 Renderer isolation
-----------------------
  contextIsolation: true
  nodeIntegration: false
  sandbox: true
  webSecurity: true
  allowRunningInsecureContent: false

The renderer cannot require('fs'). All OS access is window.lumen.

14.2 IPC allowlist
------------------
Unknown channels are not forwarded. This is defence in depth, not
a substitute for validating payloads (main checks extensions, .lumen
suffix, ".." , JSON size).

14.3 Navigation
---------------
will-navigate: only localhost:3000 in dev or packaged file:// *.html.
Dropped images must not navigate. Other http(s) -> system browser.
setWindowOpenHandler denies new windows; http(s) opens externally.

14.4 CSP (electron/main/index.ts)
---------------------------------
  default-src 'self'
  script-src 'self' 'unsafe-inline' 'unsafe-eval' 'wasm-unsafe-eval'
    Next static export uses inline boot scripts; ORT WASM needs
    eval/wasm-eval. All script bytes are still local.
  style-src 'self' 'unsafe-inline'
  img-src 'self' data: blob:
  worker-src 'self' blob:
  connect-src production: 'self' blob: data:
  connect-src dev: also localhost:3000 HTTP/WS and 127.0.0.1:7255

There is no wildcard https: in connect-src. The editor cannot call
arbitrary cloud inference even if a future bug tried fetch().

14.5 No cloud upload
--------------------
No photo multipart API, no analytics SDK, no account. Export and
print stay on-device. Command history is text in localStorage.

docs/index.html (marketing) may use GitHub's API; it is not inside
the Electron asar.

14.6 Models on disk
-------------------
Weights are local files. sync-models.mjs runs at dev/build time
(developer machine / CI), not while a user is editing under
production CSP. Packaged extraResources copies *.onnx next to the
app. Users can inspect Privacy Centre -> ONNX models path.

14.7 Media library local
------------------------
IndexedDB vista-media-library lives in the Chromium profile
(Electron userData or the browser origin). Clearing site data /
uninstalling removes it. It is not synced. Cap 200 imports.

.lumen files are user documents the user chose a path for. Autosave
is under userData (AppData), not Program Files (RELEASE_CHECKLIST).

14.8 Project file safety
------------------------
Never eval JSON. Only embedded PNG/JPEG data URLs. Future schema
opens read-only. Writes are atomic. Renderer autosave cap ~12 MB.

14.9 EXIF
---------
Canvas re-encode on export. Camera EXIF is not copied.

14.10 Known limitations (honest)
--------------------------------
  - Windows builds unsigned (SmartScreen).
  - HEIC first decode can take seconds (WASM).
  - Colour is sRGB 8-bit. No RAW, ICC, or wide gamut.
  - script-src unsafe-inline/unsafe-eval is a real CSP concession
    for Next inline boot + ORT; isolation still relies on no remote
    script hosts and connect-src self.
  - DirectML GPU EP is typed but not enabled (backend wasm).
  - Command chat UI is currently unmounted; do not advertise it as
    a visible LLM.

14.11 Privacy Centre as the in-app audit
----------------------------------------
The dialog is the user-visible counterpart to this section: host,
connect-src, userData, autosave, models folder, analytics=off.
